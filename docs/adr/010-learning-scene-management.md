# ADR 010: 학습 중인 Scene 관리 및 노출 정책

## 상태
제안됨 (Proposed)

## 컨텍스트
사용자가 홈 화면에서 자신의 학습 현황을 빠르게 확인하고 이어서 학습할 수 있도록 '학습 중인 Scene' 목록을 제공해야 합니다. 이 과정에서 어떤 데이터를 활용하여 사용자에게 유의미한 정보(진척도, 인기 여부 등)를 제공할지, 그리고 성능을 고려한 데이터 접근 방식은 무엇인지에 대한 결정이 필요합니다.

## 결정 사항

### 1. UserScene - SceneInformation 직접 연관관계 추가
- **내용**: `UserScene` 엔티티에 `SceneInformation`을 `@ManyToOne`으로 직접 연관시켰습니다.
- **이유**: 단순 ID 저장 방식보다 객체 그래프 탐색 및 JPQL의 `FETCH JOIN`을 통한 성능 최적화가 가능하며, 도메인 간의 관계를 명확히 표현할 수 있습니다.

### 2. 인기(popular) 여부 판단 기준 정의
- **내용**: Scene의 인기 여부를 `participantsCount >= 5` 조건으로 판단합니다.
- **이유**: 복잡한 통계 집계 작업 없이 초기 서비스 단계에서 '활성화된 Scene'을 사용자에게 직관적으로 보여주기 위한 가장 단순하고 효율적인 임계치 기반 방식입니다.

### 3. 진척도(progress)의 단계적 구현 (Hardcoding)
- **내용**: 현재 진척도는 **35**로 고정하여 반환하며, 코드 내에 `TODO`를 작성하였습니다.
- **이유**: 진척도 계산 로직은 퀴즈 점수, 학습 시간, 컨텐츠 이행률 등 여러 요소를 종합해야 하므로, 명확한 산식 정의 전까지는 하드코딩으로 UI 대응을 먼저 진행하고 추후 고도화하기로 결정했습니다.

## 결과
- **긍정적 효과**:
    - Fetch Join을 통해 단일 쿼리로 필요한 정보를 모두 조회할 수 있어 응답 속도가 빠릅니다.
    - 명확한 기준(임계치 5)으로 인기 여부를 투명하게 관리할 수 있습니다.
- **부정적 효과/리스크**:
    - 데이터가 적은 초기 단계에서는 인기 Scene이 하나도 없을 수 있습니다.
    - 하드코딩된 진척도는 실제 사용자의 학습 상태를 반영하지 못하므로 조속한 로직 업데이트가 필요합니다.
