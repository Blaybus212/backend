# ADR-011: 배치 기반 Scene 통계 집계 및 랭킹 관리 전략

## Status

제안됨 (Proposed)

## Date

2026-02-08

## Context

사용자에게 인기 있는 Scene 순위를 제공하기 위해서는 학습 활동 데이터를 집계하고 랭킹을 산출해야 합니다. 이 과정에서 다음과 같은 요구사항과 제약이 존재합니다:

1. **실시간 vs 스냅샷**: 실시간 집계는 성능 부담이 크고, 순위 변동이 너무 빈번하면 사용자 경험이 저하될 수 있습니다.
2. **순위 변동 추적**: 전날 대비 순위 변화를 사용자에게 보여주어야 합니다.
3. **집계 기준 시점**: 일관된 기준 시점을 정의하여 "오늘의 랭킹"을 명확히 해야 합니다.
4. **초기 구현 vs 확장성**: 초기 단계에서는 간단한 구현으로 시작하되, 향후 배치 시스템으로 확장 가능해야 합니다.

## Decision

**우리는 매일 07:00를 기준으로 Scene 통계를 스냅샷 형태로 집계하고, 이를 `SceneStatistics` 테이블에 저장하는 배치 기반 랭킹 관리 전략을 채택했습니다.**

구체적인 전략은 다음과 같습니다:

### 1. SceneStatistics 스냅샷 테이블 설계

- **내용**: `SceneStatistics` 엔티티는 특정 시점(`aggregatedTime`)의 집계 결과를 불변(immutable) 스냅샷으로 저장합니다.
- **필드 구성**:
  - `aggregatedTime`: 집계 기준 시각 (매일 07:00)
  - `score`: 해당 기간 동안 누적된 점수
  - `rank`: 해당 시점의 순위 (1~N)
  - `difference`: 전날 랭킹과의 차이 (양수: 상승, 음수: 하락)
- **이유**: 과거 랭킹 데이터를 보존하여 순위 변동 추적이 가능하며, 실시간 계산 부담을 제거합니다.

### 2. 집계 시점 정책: 매일 07:00 기준

- **내용**: 모든 통계는 매일 **07:00**를 기준으로 집계되며, API 조회 시점에 따라 참조하는 집계 데이터가 달라집니다:
  - 현재 시각이 07:00 이후 → 어제 07:00 집계 데이터 사용
  - 현재 시각이 07:00 이전 → 그제 07:00 집계 데이터 사용
- **이유**: 
  - 새벽 시간대(07:00)는 사용자 활동이 적어 배치 작업에 적합합니다.
  - 하루 단위 랭킹 변화를 명확히 구분할 수 있습니다.
  - 사용자가 아침에 접속했을 때 "어제의 인기 순위"를 확인할 수 있습니다.

### 3. 초기 구현: DataLoader를 통한 더미 데이터

- **내용**: 현재는 `DataLoader`에서 어제/그제 07:00 기준 더미 통계 데이터를 삽입하여 API 동작을 검증합니다.
- **이유**: 실제 배치 시스템 구축 전에 API 로직과 프론트엔드 연동을 먼저 완료하기 위함입니다.

### 4. 향후 확장: 배치 프로세스로 전환

- **내용**: 추후 Spring Batch 또는 별도 스케줄러를 통해 매일 07:00에 자동으로 통계를 집계하고 `SceneStatistics` 테이블을 갱신하는 배치 작업을 구현합니다.
- **집계 로직**:
  1. 전날 00:00 ~ 23:59 사이의 학습 활동 데이터 수집
  2. Scene별 점수 계산 (학습 시간, 퀴즈 완료 등 가중치 적용)
  3. 점수 기준 내림차순 정렬 후 순위 부여
  4. 전날 랭킹과 비교하여 `difference` 계산
  5. `SceneStatistics` 테이블에 새로운 스냅샷 레코드 삽입

## Trade-off Analysis

### 1. 배치 기반 스냅샷 방식 (선택됨)

**장점 (Pros):**

- **성능**: API 조회 시 단순 SELECT 쿼리만 수행하므로 응답 속도가 빠릅니다.
- **일관성**: 동일 시점에 조회한 사용자는 모두 같은 랭킹을 보게 됩니다.
- **이력 관리**: 과거 랭킹 데이터를 보존하여 트렌드 분석이 가능합니다.
- **순위 변동 추적**: 전날 대비 순위 변화를 명확히 계산할 수 있습니다.

**단점 (Cons):**

- **실시간성 부족**: 최신 학습 활동이 즉시 반영되지 않습니다.
- **배치 의존성**: 배치 작업이 실패하면 랭킹 데이터가 갱신되지 않습니다.
- **스토리지 증가**: 매일 스냅샷을 저장하므로 데이터가 누적됩니다.

### 2. 실시간 집계 방식 (기각됨)

**장점 (Pros):**

- **즉시성**: 학습 활동이 즉시 랭킹에 반영됩니다.

**단점 (Cons):**

- **성능 부담**: 매 API 요청마다 복잡한 집계 쿼리를 실행해야 합니다.
- **순위 변동 추적 어려움**: 전날 랭킹을 별도로 저장하지 않으면 비교가 불가능합니다.
- **일관성 문제**: 동일 시점에 조회해도 사용자마다 다른 랭킹을 볼 수 있습니다.

## Consequences

- **긍정적 효과**:
  - 랭킹 조회 API의 응답 속도가 빠르고 안정적입니다.
  - 순위 변동 정보를 통해 사용자에게 유의미한 인사이트를 제공할 수 있습니다.
  - 향후 배치 시스템으로 확장 시 기존 API 로직을 변경할 필요가 없습니다.

- **부정적 효과/리스크**:
  - 초기 단계에서는 더미 데이터에 의존하므로 실제 사용자 활동이 반영되지 않습니다.
  - 배치 작업 구현 전까지는 `DataLoader`에서 수동으로 데이터를 관리해야 합니다.
  - 07:00 기준 정책이 사용자 행동 패턴과 맞지 않을 경우 조정이 필요할 수 있습니다.
