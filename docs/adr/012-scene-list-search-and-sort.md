# ADR 012: 오브젝트 리스트 검색 및 정렬 방식 결정

## 상태
제안됨 (Proposed)

## 컨텍스트
사용자가 다양한 학습 오브젝트(Scene)를 탐색할 수 있는 `GET /scenes` API를 구현하는 과정에서, 카테고리 필터링, 키워드 검색, 그리고 다양한 기준(가나다순, 인기순)에 따른 정렬 기능이 필요했습니다. 이를 위해 파라미터 타입 결정, 데이터베이스 스키마 조정, 동적 검색 쿼리 작성 방식에 대한 기술적 결정이 이루어졌습니다.

## 결정 사항

### 1. 정렬 조건의 Enum화 (`SceneListOrder`)
- **내용**: 정렬 기준을 단순 문자열이 아닌 `SceneListOrder` Enum으로 정의하여 관리합니다.
- **이유**:
    - 허용되지 않은 정렬 값이 입력되는 것을 API 레벨에서 방지(Type-safe)할 수 있습니다.
    - 정렬 명칭(가나다순, 인기순)과 내부 코드(alphabetical, popularity)를 명확히 매핑하여 가독성을 높입니다.
    - `Converter`를 통해 `alphabetical` 등 영문 값을 입력받아 Enum으로 자동 변환합니다.

### 2. SceneCategory 컬럼 길이 확장 (20 -> 50)
- **내용**: `SceneInformation` 엔티티의 `category` 컬럼 길이를 20에서 50으로 증가시켰습니다.
- **이유**: `AUTOMOTIVE_ENGINEERING`, `MANUFACTURING_ENGINEERING` 등 구체적인 공학 분야를 나타내는 Enum 값들이 기존 20자 제한을 초과하여 데이터 저장 시 `DataException`이 발생하는 문제를 해결하기 위함입니다.

### 3. JPQL을 이용한 동적 검색 및 필터링
- **내용**: `findByCategoryAndQuery` 메서드에서 JPQL의 `:param IS NULL OR 컬럼 = :param` 패턴을 사용하여 카테고리와 검색어의 존재 여부에 따라 동적으로 동작하는 쿼리를 작성했습니다.
- **이유**: QueryDSL 등의 복잡한 라이브러리 추가 없이 Spring Data JPA의 기본 기능을 활용하여 간단하고 직관적으로 동적 쿼리 요구사항을 만족할 수 있습니다.

### 4. LIKE %query% 기반 키워드 검색
- **내용**: 제목(`title`)과 영어 제목(`engTitle`)에 대해 `LIKE %keyword%` 방식으로 부분 일치 검색을 수행합니다.
- **이유**: 데이터량이 초기 단계이므로 별도의 전문 검색(Full-text Search) 엔진 없이도 요구사항을 충족하며, 구현 속도가 빠릅니다.

## 결과
- **긍정적 효과**:
    - 타입 안정성이 보장된 정렬 및 필터링 기능을 제공합니다.
    - 긴 컬럼 데이터를 안전하게 저장할 수 있도록 스키마가 개선되었습니다.
    - 단일 메서드로 다양한 검색 옵션을 처리할 수 있어 코드가 간결합니다.
- **부정적 효과/리스크**:
    - `LIKE %query%` 방식은 인덱스 활용이 어려워 데이터가 급증할 경우 조회 성능 저하가 발생할 수 있습니다.
    - 정렬 기준이 많아질 경우 `SceneService` 내의 조건문이 복잡해질 수 있으므로 추후 객체지향적인 정렬 전략(Strategy Pattern 등) 고려가 필요할 수 있습니다.
